## Что в этом обновлении

Первое обновление зависимостей ядра с 2017 года. Java 8 / Minecraft 1.7.10 / Forge 10.13.4.1614 — **совместимость с модами сохранена** (guava 17, gson 2.2.4, Scala 2.11 и ASM 5 намеренно не тронуты — против них собраны моды 1.7.10).

| Компонент | Было | Стало |
|---|---|---|
| log4j2 | 2.0-beta9 (диапазон Log4Shell / CVE-2021-44228) | **2.17.2** |
| LMAX disruptor (async-логирование) | 3.2.1 | 3.4.4 |
| snakeyaml (server.yml / worlds.yml) | 1.16 | 1.33 |
| netty | 4.0.10.Final | 4.0.56.Final (последняя 4.0.x) |
| commons-dbcp2 (пул БД) | 2.1.1 | 2.9.0 |
| mysql-connector-java | 5.1.31 | 5.1.49 (последняя 5.1.x — старые MySQL-серверы продолжают работать) |

Сопутствующие исправления:

- Кастомные log4j-плагины ядра (формат консоли, очистка цветов в файловых логах) портированы на log4j 2.17; JMX-регистрация log4j отключена — её блокировал FMLSecurityManager и это сыпало ошибку при каждом старте.
- Проверка обновлений Forge больше не спамит стектрейсом при каждом запуске: для навсегда замороженного Forge 1.7.10 она отключена по умолчанию (вернуть: `-Dforge.versionCheck=true`).
- CI-проверка релиза стала строже: сервер обязан не только собраться, но и запуститься (`Done`), и в логах не должно быть ошибок инициализации log4j.

Известный крайний случай: редкие коремоды, которые лезут во **внутренности** log4j-core (не в стабильный log4j API), могли собираться против 2.0-beta9. Обычным модам обновление безразлично. Если с вашим набором модов что-то пошло не так — вернитесь на v0.1.6 и создайте issue со списком модов.

Дальше по плану — постепенная работа над запуском ядра на современных JVM (цель: Java 25). Дорожная карта: `docs/06-modernization-notes.md`.
