## Сервер живой — и запускается на Java 25 🚀

Главное в этом релизе: **ядро теперь стартует и работает на современных JVM — вплоть до Java 25 (LTS)** — при полном сохранении поддержки Java 8. CI проверяет оба конца на каждой сборке: один и тот же jar загружается до `Done` и на Temurin 8, и на Temurin 25.

| Java | Статус |
|---|---|
| 8 | Полная поддержка — родной путь запуска, не менялся |
| 9–24 | Должно работать — запуск адаптируется к версии автоматически (`start.sh` сам добавляет нужные флаги JVM) |
| 25 (LTS) | Полная поддержка — проверяется CI на каждой сборке |

**Важно про моды**: само ядро на Java 25 работает, но отдельные моды и коремоды 1.7.10 могут использовать внутренности JVM, удалённые после Java 8 — тестируйте свою сборку модов. Scala-моды на современных JVM не заработают (Scala 2.11 там не запускается). Если что-то не так — Java 8 остаётся полностью рабочим вариантом.

### Что сделано технически

- Обход `URLClassLoader`-каста launchwrapper: собственная реализация цепочки запуска (`ModernJavaLaunch`) для Java 9+, на Java 8 работает нетронутый стоковый путь
- Генерация сервисных делегатов через `defineHiddenClass` на Java 15+ (замена удалённого `Unsafe.defineAnonymousClass`)
- Ядро переживает отсутствие SecurityManager (Java 17+ / JEP 486)
- Запись `@ObjectHolder`-полей через `Unsafe` вместо удалённого `sun.reflect.ReflectionFactory`
- `EventSubscriptionTransformer` исправлен под строгую валидацию дескрипторов ASM 9 (ломалась регистрация событий Forge)
- ASM обновлён до 9.10.1 — трансформеры читают современные class-файлы
- `start.sh` определяет версию Java и сам добавляет `--add-opens` (9+) и `--sun-misc-unsafe-memory-access=allow` (23+)
- Новый обязательный CI-джоб: каждая сборка загружается на Java 25

Включает также все обновления зависимостей из v0.1.7 (log4j 2.17.2 и др.).
