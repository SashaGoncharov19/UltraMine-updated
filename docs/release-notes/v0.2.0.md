## The server is alive — and runs on Java 25 🚀

The headline of this release: **the core now starts and runs on modern JVMs, up to Java 25 (LTS)** — with full Java 8 support preserved. CI verifies both ends on every build: the very same jar boots to `Done` on Temurin 8 and on Temurin 25.

| Java | Status |
|---|---|
| 8 | Fully supported — the original launch path, untouched |
| 9–24 | Expected to work — the launch adapts to the JVM version automatically (`start.sh` adds the required flags itself) |
| 25 (LTS) | Fully supported — CI-verified on every build |

**A note on mods**: the core itself runs on Java 25, but individual 1.7.10 mods and coremods may rely on JVM internals removed after Java 8 — test your modpack. Scala-based mods will not work on modern JVMs (Scala 2.11 cannot run there). If anything misbehaves, Java 8 remains a fully supported option.

### Technical changes

- Workaround for launchwrapper's `URLClassLoader` cast: an own implementation of the launch flow (`ModernJavaLaunch`) for Java 9+; on Java 8 the stock path runs untouched
- Service delegates are generated via `defineHiddenClass` on Java 15+ (replacement for the removed `Unsafe.defineAnonymousClass`)
- The core survives the absence of a SecurityManager (Java 17+ / JEP 486)
- `@ObjectHolder` fields are written through `Unsafe` instead of the removed `sun.reflect.ReflectionFactory`
- `EventSubscriptionTransformer` fixed for ASM 9's strict descriptor validation (Forge event registration was breaking)
- ASM upgraded to 9.10.1 — the transformers can read modern class files
- `start.sh` detects the Java version and adds `--add-opens` (9+) and `--sun-misc-unsafe-memory-access=allow` (23+) itself
- New mandatory CI job: every build is booted on Java 25

Also includes all dependency updates from v0.1.7 (log4j 2.17.2 and others).
