## Real modpacks, real fixes 🧩

This release is the result of booting an actual 294-mod server pack (GT New Horizons) on the core and fixing everything that broke. **293 of those 294 mods now reach mod construction and pre-init** — GregTech, Thaumcraft, AE2, Railcraft, Forestry and the whole GTNH coremod stack among them.

Almost every failure had the same cause: **the core had quietly changed a shape that coremods patch**. A coremod compiled against stock 1.7.10 looks for a field of a given name and type, an allocation site, a specific local-variable layout — where the core differed, the coremod's patch silently missed while the rest of its rewrite still applied, and the class failed to load, taking every mod that depended on it down with it.

### What this means for server owners

- **Coremod-heavy packs work far better.** Six such divergences are fixed, so mods that optimize NBT, extend entity data, patch world updates or configure their own loggers now apply cleanly.
- **Modern log4j no longer breaks mods.** The core ships log4j 2.17.2 (Log4Shell-free) while mods are compiled against Forge's 2.0-beta9. Removed factory signatures are bridged and the relocated `core.helpers` package is remapped, so mods that set up their own log files (GregTech, CoFHCore) work on the modern library.
- **Safer networking.** Incoming packets are rate-limited per connection (vanilla 1.7.10 has no limit at all — a spamming client could grow the receive queue until the server ran out of memory), and two crash vectors from crafted packets are closed: out-of-range window-click slots and enchantment-button ids.
- **Faster class loading.** The core no longer parses and re-emits every single class at startup; untouched classes now pass through byte-identical.

### Known incompatibilities (documented, with workarounds)

- **ArchaicFix's Phosphor lighting** — set `B:enablePhosphor=false` in `config/archaicfix.cfg`. Chunk light lives off-heap here, so Phosphor has no vanilla light arrays to work against. The rest of ArchaicFix is fine.
- **EndlessIDs / NEID** — these extend block ids past vanilla's 4096 by extending the vanilla block arrays, which this core replaced with off-heap storage. Packs that need more than 4096 block ids (GTNH asks for 10617) cannot run yet; widening the chunk storage format is the next big step.

### Also in this release

- `EnumHelper` and `@ItemStackHolder` injection work on modern JVMs (mods that add enum constants no longer need Java 8 internals)
- launchwrapper's transformer list is copy-on-write — coremods that register transformers during class loading no longer trigger a `ConcurrentModificationException`
- a failed launch now prints its real stack trace instead of losing it to the async logger
- CI gained a real-modpack boot test with self-diagnosing failure output

Java 8 and Java 25 remain verified on every build.
